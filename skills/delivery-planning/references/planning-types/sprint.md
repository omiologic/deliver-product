# Sprint planning

Use this type only when an explicit request, owner-produced state, or consumer convention supplies a real time box. Add its fixed boundary, ordered candidate outcomes, capacity or dependency constraints that are actually known, and the criteria for accepting work into the commitment.

Keep unfinished or uncertain work visible rather than implying it fits. Do not invent estimates, velocity, assignments, or priority. A sprint proposal does not start work or make included WorkItems canonically ready.
