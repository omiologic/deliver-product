# Feature-development planning

Use this type for one bounded, independently testable product or system capability. Add the user-visible or contract-level behavior, affected interfaces, excluded adjacent capabilities, acceptance criteria for the complete feature, and verification at the narrowest meaningful integration boundary.

Decompose only where separate results have real dependency, verification, approval, or execution boundaries. Do not turn implementation layers into independent outcomes when none can satisfy a criterion on its own. Use bounded-outcome planning for a small reversible change that needs no feature-specific reasoning.
